## 2. How each feature works

### Vehicles (`shared/m3.js`, `server/rooms/CityRoom.js`, `src/economy.js`, `src/jobs.js`, `src/main.js`)
- Buy at the **Showroom** POI (within 300 px). Cash first, then Bank, never negative (same rule as the hospital fee). The vehicle is parked on the open lot **south** of the Showroom (`y + 270`) — the building itself is blocked, so parking at the POI would strand it where nobody can mount it (found by the test run, fixed in both server and offline economy).
- `E` (or the Lên xe button) mounts the nearest owned vehicle within 80 px. Speed applies to movement (`vehicleSpeed` × `speedWithHunger`, sprint on foot only) and to Shipper deadlines: **deadline = distance / vehicle speed + 30s, locked at accept**; reward uses the locked multiplier of the vehicle ridden at accept. Changing vehicle mid-order does not change the deadline.
- Motorbike drains fuel (100% = 8.000 px); bicycle drains durability (100% = 50.000 px). At 0 the vehicle is pushed at walk speed (180 px/s) and the player is told `out_of_fuel` / `worn_out`. Refuel (5.000đ) / repair (10.000đ) at the shop, within 300 px.
- Shipper capacity (10/13/18 kg) is defined but **not enforced** — the P0 order pool has no weight field.

### Taxi (`shared/m3.js` §3.4.2, `server/rooms/CityRoom.js`, `src/jobs.js`)
- Job `taxi_driver` + **motorbike required** (bicycle cannot carry a passenger). "Nhận khách" toggles taxi mode. NPC customers wait at sidewalk corners of road intersections and appear only when < 4 real players are in the room (max 4 customers, despawn after 5 min).
- Real players: driver invites a nearby player → they accept → ride. Dropoff (button, or driver dismounts) completes the trip.
- Fare = 1.000đ/100 px travelled, clamped 5.000–20.000đ. **Tax 5% (LOCKED, buyer pays):** passenger pays fare + 5%; driver receives fare + night bonus (SYSTEM, +30% capped at 6.000đ). If the passenger cannot pay in full, the driver gets only what was actually paid — no SYSTEM subsidy of the missing fare (same never-negative rule as the hospital fee). **NPC passenger fare is paid by SYSTEM** (the NPC has no wallet) — driver still gets fare + night bonus.
- Offline: same engine with local NPC customers (fare paid by SYSTEM, `economy.grant('taxi_fare')`).

### Doctor mini-game (`src/jobs.js`, `index.html` #revivePanel, server revive)
- Clicking Hồi sinh on a fainted player opens the rhythm panel: 10 beats × 1.100 ms, tap when the marker is inside the green zone (42–58%). Accuracy ≥ 90% → victim gets 30 + 20 = 50 HP; below that, 30 HP. The client-sent accuracy is clamped 0–100 and the +20 bonus is computed **server-side** (`M3.doctorMinigameBonus`) — the client cannot forge it. Reward (25.000đ), 60s cooldown and the 2/60min pair cap are unchanged.

### Online self-faint SFX fix (known M3 gap)
- The server now broadcasts an explicit **`fainted`** message `{playerId, name, x, y, at}` to the whole room when a player faints (in addition to the doctor-only `faint_alert`). The client plays `DTA_SFX.faint` from `onFainted` for self, plus the `syncSelf` isFainted edge as fallback; both funnel through a 3-second throttle so one faint never plays twice. No new SFX methods were added — M4 reuses existing motifs.

### Motel (`shared/m3.js` §8.2, `server/rooms/CityRoom.js`, `src/economy.js`)
- Rent 50.000đ / 24h real at the Motel POI (within 300 px); renew extends **from the old expiry** (not from now), max 7 days ahead. Room gives a 10-slot chest.
- Offline: chest lives in the same `localStorage` wallet as everything else (`dta_m2_wallet_v1`). Online: per-session server state keyed by `sessionId` — a reconnect gets a new session, so vehicles/motel do **not** survive a rejoin yet (Supabase assets wiring is M2/M5 work).
- Unpaid rent → room repossessed: chest state `held` for 24h after expiry (locked until rent is paid), then `deleted` (items gone).

## 8. Batch 2026-11-25 08:27 — dog streak (real cause), traffic, shipper multi-shop, test mode (local only, NOT pushed)

User phone-tested 08:22 (2 screenshots) and reported: dog streak STILL there; "Chưa có xe cộ di chuyển trên đường à"; shipper should take orders from many shops (50% warehouse / 50% shops); add a test mode for free money + speed.

### (1) Dog streak — real root cause (top priority)
The 08:22 screenshot STILL shows the same long flat tan smear with a magenta-red fringe on its bottom edge, ~80% of screen width, lying across the road. The PNG is innocent (`prop-dog-full.png` clean tan puppy, 301×360, corner alpha 0) and `spawnAnimal()` sizes it correctly (30px wide, ~36px tall). The bug is at RUNTIME in `updateAnimals()` (`src/main.js`): PixiJS derives a Sprite's rendered width from its scale (`width = |scale.x| × texture.width`), and setting `.width` only sets `scale.x = w / texture.width` once. The old flip did `a.container.scale.x = -1`, which reset the dog's rendered width to the full texture width (301px) while the height stayed ~36px — exactly a 301×36 flat tan smear (301px ≈ 77% of a 390px phone screen at zoom 1.0x), with the keyed-out shadow residue smeared along the bottom edge. The dog only needs to walk left once; the streak then stays forever (scale.x stays ±1). It lies on the road because animals walk straight between open points and cross road bands. Fix: `spawnAnimal()` stores `baseScaleX = spr.scale.x` and the flip uses the sign only (`-Math.abs(baseScaleX)` / `+Math.abs(baseScaleX)`). Audit of every other flip: NPC walkers now flip the inner face Container (a plain Container — mirroring it cannot change any size; the walker object keeps `face` because `npc.userData` is replaced by the NPC object); the player and remote players already flip their face container; the ride sprite is never flipped. New check `test/animal-flip-check.js`: a PixiJS-semantics stub reproduces the old bug exactly (30px → 301px on `scale.x = -1`) and proves the new pattern holds 30×36px (dog) / 22×43px (cat) over 200 flip cycles.

### (2) Moving traffic
8 ambient vehicles (4 cars + 4 motorbikes) drive the road bands (`ROAD_BANDS` 1140/2340/3540, width 180) in both directions at 200–300 px/s, two right-hand lanes per band (offsets +45/+135, lane follows direction), wrapping at the map edges (±120px). Client-side, visual only — no collision, the server never sees them. Orientation is by ROTATION only, never a `scale.x` flip (the dog-streak rule); car texture is wide (741×360, side view), motorbike tall (204×360, top-down), so their base rotations differ per axis. The 3 parked cars + 5 parked showroom motorbikes are untouched. Movers are now y-sorted with the player (`world.sortableChildren = true`, `zIndex = y` on player/NPCs/animals/remotes/traffic/taxi customers; static props stay at zIndex 0 below them, as the player already was); UI world children (delivery arrow, radial menu, bubble, 💬 hint, guide label) are pinned at 99999 and the VFX layer at 100000 so sorting cannot bury them. New check `test/traffic-check.js` (21 checks incl. a 60 s simulation: every vehicle stays on its road band).

### (3) Shipper multi-shop orders (user decision)
Orders are picked up from many places, not just the warehouse: 50% Kho Hàng Trung Tâm, 50% shops — Cửa Hàng Tiện Lợi 24/7 (2895,1590), Khu Nhà Trọ (2910,2865), Chợ (4155,4065), Quán Cà Phê (2700,4380). `shared/m3.js`: `SHIPPER_SOURCES` + `pickOrderSource()` (50/50, seeded in tests) + `nearestShipperSource()`; `pickDeliveryPoint()` takes an `excludePoiId` so a delivery is never the pickup shop itself. Server (`CityRoom.js`): every pool slot carries a pickup source (re-rolled on release); accept takes the NEAREST source to the player and a free slot FOR that source — nowhere near a source → `TOO_FAR` (as before), near a source whose slots are all taken → `ORDER_TAKEN`. The order carries `pickupId/pickupName/pickupX/pickupY`, mirrored into Colyseus state (`orderPickupX/Y/Name` in `server/schema.js`, via `src/net.js` + `src/main.js` `syncSelf`) so the job panel can show it. Everything else unchanged: first-come-first-served 12-slot pool, deadline = distance/speed + 30s, server-calculated reward. Server tests +11 (see §9).

### (4) Test mode (`?test=1`)
OFF by default; no test UI at all without the param. With `?test=1` a small collapsible TEST panel appears at the left edge (left 10px, top 210px — below the HUD panel and the status pill, clear of the zoom buttons).
